Tandem · PM Operating Kit

Guide

This is the end-to-end walkthrough: from an empty repo to your first story shipped and closed under the gates. Follow it once in order and you will have used every load-bearing part of Tandem. After that, Playbook is the day-to-day lookup.

If you only need prerequisites and install commands, Getting started is the short version. This page assumes you have Node.js ≥ 18 and Claude Code.

0 · Install and bootstrap

/plugin marketplace add DATA-AI-XYZ/Tandem
/plugin install tandem@data-ai-xyz

Then, in a Claude Code session opened on your project:

/tandem:session-start

session-start orients the session — it reads active work, recent decisions, and the board, then tells you which hat to wear and what the next step is. On a fresh repo there is nothing to read yet, so run the installer:

/tandem:install

That materializes _00-Project-Management/, wires the pm:* scripts into package.json, registers the three hooks, pins your folder layout, and renders the board. Verify:

npm run pm:doctor

pm:doctor exits non-zero only on real wiring problems, so it is safe to use as a CI gate.

One-time question. The installer asks what kind of project this is — web-app, mobile, cli, library, backend-service, data-pipeline, power-platform, or automation. The answer is written to 90-Standards/PROJECT-CONTEXT.md and tailors later guidance. Answer honestly; you can edit the file afterwards.

1 · Anchor the strategy

Every epic must trace to a business outcome, and Tandem will refuse to write one that does not. So strategy comes first.

Write a North Star into 00-Strategy/NORTH-STAR.md — one paragraph on what winning looks like beyond this quarter. Then:

/tandem:draft-okrs

This runs as the Founder hat. It reads the North Star, the previous quarter's OKRs, and any recent retros, and produces 00-Strategy/OKR-YYYY-Qx.md with objectives and measurable key results. Expect to push back on the first draft — key results that are not numbers are not key results.

2 · Draft the PRD and the epic

/tandem:draft-prd

Turns an OKR key result (or raw notes) into a PRD under 20-Requirements/. Skip it only if the scope is genuinely obvious; the PRD is what an epic points at when there is no single OKR to cite.

/tandem:draft-epic

Produces 30-Epics/EPIC-NN-<slug>.md. The epic must carry either okr: or prd_section: in its frontmatter — if you cannot say which outcome it moves, Tandem asks before writing rather than inventing a justification.

An epic covers goal, scope, explicit out-of-scope, measurable success criteria, dependencies, data touched, and risks. Out-of-scope is not filler: it is what stops the epic growing silently.

3 · Decompose

/tandem:split-into-features

Breaks the epic into FEAT-NN.M files under 31-Features/EPIC-NN/. A feature is a slice you could ship and demo on its own.

/tandem:split-into-stories

Breaks a feature into STORY-NN.M.PP files — and creates the paired testplan for each story in the same response. This pairing is not optional and not deferred:

  • every acceptance criterion in the story maps to at least one test case in the testplan;
  • every test case carries a runnable Command: that Claude can execute unattended.

If a criterion cannot be expressed as something a machine can check, that is a signal the criterion is vague — rewrite it before moving on.

Optionally, run a quality pass before refining:

/tandem:critique

Advisory only. It reviews a planning artefact against the kit's check set and reports; it never rewrites the file.

4 · Refine to ready (the DoR gate)

/tandem:refine-backlog

Runs the Definition of Ready checklist as the PM hat. A story is promoted to ready only if all of it passes: paired testplan exists, every criterion maps to a test case, every test case has a runnable command, dependencies are done or scheduled, an estimate is set, and risks are written down.

If anything is missing the command stops, lists the gaps, and asks. It never silently promotes. That refusal is the point of the gate.

For an older backlog, run /tandem:triage-backlog first. It checks whether each item is still true — not delivered by a later epic, not a duplicate, premise intact — before refine-backlog asks whether it is ready. Status fields lag reality; triage is how the backlog stays honest.

5 · Execute

For a single story:

/tandem:execute-story

For a planned group of them, first work out the order:

/tandem:execution-strategist

which groups ready stories into batches by dependency chain and shared-files affinity, then:

/tandem:execute-batch          # sequential, one batch end-to-end
/tandem:execute-batch-parallel # file-disjoint stories concurrently, one sub-agent each

Execution runs as the Dev hat. The story flips to in-progress with a timestamp in the same edit as the status change — never as a separate save.

To run the whole plan unattended:

/tandem:autopilot

Autopilot drives phase → batches → close, checkpoints as it goes, halts on any failure, pauses itself near your Claude usage limit, and resumes when the window resets.

6 · Verify

/tandem:run-testplan

Runs as the QA hat and executes every test case in the paired testplan. When a test case fails, Tandem files a structured BUG-YYYYMMDD-NN under 34-Bugs/ before reporting the failure back to you — reproduction steps, environment snapshot, a first hypothesis, and a fix direction a junior developer can act on.

You do not ask for the bug. You get it.

7 · Close out (the DoD gate)

/tandem:close-out-story

Runs the Definition of Done checklist: every acceptance criterion ticked, the testplan run with all test cases passing (or failures linked to bugs), project quality gates green, the AI-code review recorded, frontmatter flipped to done with completed_at set, and 42-Monitor/MONITOR.md updated in the same response.

When the last story in a phase closes:

/tandem:close-phase

which gates on every story being done, compiles the retro, and merges the phase branch.

8 · Watch it

The board regenerates itself — the Stop hook runs pm:dash whenever your plan changes — but you can force it:

npm run pm:all   # wiki-stamp check → lint → monitor → dash → docs

Open _00-Project-Management/42-Monitor/DASHBOARD.html. That is the Command Center: the live interactive view of everything above. The published live demo is the same file generated from a sample project.

On a cadence:

/tandem:weekly-monitor   # Friday summary; flags stalls and blocks
/tandem:monthly-retro    # monthly retrospective
/tandem:reflect          # end-of-session improvements, which you approve before they apply
